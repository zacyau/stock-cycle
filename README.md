# 长期走势 · 回撤 · 牛熊周期分析

一个基于 **FastAPI + Jinja2 + ECharts** 的单页 Web 应用。输入任意 A 股 / ETF / 指数代码，
自动抓取**腾讯行情后复权**日线数据，渲染四个分析模块：

| # | 模块 | 说明 |
|---|------|------|
| ① | 对数坐标下的长期年化收益 | 净值曲线（起点 = 1.0x），纵轴对数刻度，标注 CAGR 与区间倍数 |
| ② | 历史最大回撤幅度及时长 | 水下回撤曲线 + 最大回撤区间 / 下跌历时 / 修复情况 |
| ③ | 牛熊阶段的划分 | ±20% 摆动法（可切换 ±15% / ±25%、月线 / 日线），熊市色带 + 阶段时长色带 + 统计卡 |
| ④ | 不同时间尺度下的涨跌统计 | 1 周 ~ 5 年、年初至今、距前高、自定义基准日以来的涨跌幅（涨红跌绿） |

## 快速开始

```bash
cd stock-cycle

# 依赖（沙箱内已预装 fastapi / uvicorn / jinja2 / pandas / numpy / requests）
pip3 install -r requirements.txt

# 启动
python3 app.py
# 或：uvicorn app:app --host 0.0.0.0 --port 8000
```

浏览器打开 <http://127.0.0.1:8000/> 即可。

## 数据源与口径

- **接口**：`https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param={code},day,{start},{end},640,hfq`
- **复权**：`hfq` 后复权。这是本项目的基础——实测腾讯的**不复权序列对 ETF 存在异常跳变**
  （如 510500 在 2015 年前后价格失真约 3.5 倍），只有后复权序列在分段拼接后完全连续。
- **分段抓取**：单次最多返回约 640 根 K 线，因此按 2 年切片、**从最新一段往前回溯**；
  某一段返回空数组即判定已早于上市首日，停止回溯。
- **月线**：腾讯该接口不支持 `month` 频率（返回 HTTP 501），月线由日线按月重采样得到
  （取每月最后一个交易日的收盘价），与参考口径一致。
- **接口限制**：腾讯接口存在 WAF 随机拦截（返回 HTML 而非 JSON），已通过 `Referer` 头 +
  指数退避重试 + SQLite 长期缓存规避。若连续失败，可点页面上的「刷新数据」，或稍后重试。

### 关键指标口径

| 指标 | 口径 |
|------|------|
| 净值倍数 | 后复权收盘价 / 首个交易日收盘价，起点恒为 1.0x |
| CAGR | `期末倍数 ^ (365.25 / 跨度自然日) - 1` |
| 回撤 | `净值 / 历史最高净值 - 1`，恒 ≤ 0 |
| 最大回撤时长 | 峰值日 → 修复日；若尚未修复则计至最新交易日 |
| 下跌历时 | 峰值日 → 谷底日（对应参考图中斜线旁标注的 `40m`） |
| 牛熊划分 | ±阈值摆动法，默认输入**月度**收盘价，与参考口径一致 |

### 摆动法的「末段」处理

最末一段若尚未被反向摆动确认（例如自峰值回落但未达阈值），按**自身涨跌方向**归类并入统计，
色带上以**半透明**表示。这与参考做法一致。

## 路由

| 路由 | 说明 |
|------|------|
| `GET /` | 渲染整页。`?code=sh000905` 切换标的，`?refresh=1` 强制刷新，`?since=2024-09-24` 指定自定义基准日 |
| `POST /api/refresh?code=sh510500` | 清除该标的缓存并重新全量抓取 |
| `GET /api/data?code=sh510500` | 返回完整 JSON 载荷，便于外部程序调用 |
| `GET /api/health` | 健康检查 |
| `GET /docs` | FastAPI 自动生成的接口文档 |

> 参数面板（月线 / 日线、±15% / ±20% / ±25%）的全部组合在服务端**一次性算好并内嵌**到 HTML，
> 前端切换时零网络请求、即时重算。

## 常见问题

**为什么净值倍数与某些行情软件不完全一致？**
本项目使用二级市场成交价的后复权口径。若换成基金单位净值（复权净值）口径，全周期倍数会略高
（约 2.70x）。两者形态、回撤、牛熊划分完全一致，差异仅来自口径。

**为什么指数没有复权？**
指数本身不含分红再投资概念，腾讯对指数直接返回原始点位序列，程序已自动兼容。

**数据多久更新一次？**
SQLite 缓存默认 6 小时有效期，且最后一天距今超过 4 个自然日即自动重新抓取；
页面上的「刷新数据」按钮可随时强制更新。
